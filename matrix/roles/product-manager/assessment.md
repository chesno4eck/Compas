# Рекомендации по оценке: Продакт-менеджер

Навык SFIA общий. Ниже — что проверять **в контексте этой роли**. Если навыка нет в списке — используйте универсальный текст SFIA.

## PROD — Управление продуктом

### Уровень 2

**Проверять:**

- Помогает с продуктовыми задачами под менторством: описание фич, релиз-ноты, FAQ
- Собирает обратную связь пользователей и стейкхолдеров по шаблону
- Следит за базовыми метриками использования по дашборду команды

**Артефакты:**

- Оформленная пользовательская история или бриф фичи
- Сводка обратной связи по фиче
- Скрин дашборда с комментариями

### Уровень 3

**Проверять:**

- Ведёт бэклог фичи или небольшого продукта: приоритизация, критерии приёмки
- Следит за результатами запусков, действует по данным и обратной связи
- Координирует контент для внедрения (справка, онбординг, коммуникации) с командой

**Артефакты:**

- Приоритизированный бэклог с обоснованием
- Разбор после запуска с метриками
- Короткий go/no-go по фиче

### Уровень 4

**Проверять:**

- Владеет дорожной картой продукта или стрима; балансирует ценность, риски, ёмкость команды
- Использует исследования, интервью и аналитику для поиска проблем и приоритизации
- Организует бета, пилот и запуск; отслеживает показатели продукта

**Артефакты:**

- Дорожная карта на квартал с целями по результату
- Документ исследования (проблема → решение → метрики)
- План запуска и итоги первых недель

### Уровень 5

**Проверять:**

- Ведёт полный жизненный цикл продукта или линейки: видение, позиционирование, сегменты
- Выбирает подход к разработке продукта (ритм исследования и поставки)
- Планирует вывод из эксплуатации или переход; координирует пользовательское тестирование на масштабе

**Артефакты:**

- Стратегия и видение продукта
- Позиционирование и сегментация
- План вывода, перехода или смены направления с метриками

## REQM — Определение и управление требованиями

### Уровень 2

**Проверять:**

- Собирает простые требования по шаблону (пользовательская история, критерии приёмки)
- Помогает вести бэклог и фиксировать изменения требований

**Артефакты:**

- Пользовательские истории с критериями приёмки
- Фиксация изменений в бэклоге

### Уровень 3

**Проверять:**

- Самостоятельно собирает и документирует требования для фичи
- Ставит под сомнение неясные требования; прослеживаемость к цели и метрике
- Управляет запросами на изменения в рамках политики команды

**Артефакты:**

- Спецификация фичи (PRD)
- Матрица прослеживаемости (цель → требование → тест или метрика)
- Запись согласования изменения объёма

### Уровень 4

**Проверять:**

- Ведёт требования для инициатив средней сложности; организует работу со стейкхолдерами
- Эффективно приоритизирует с компромиссами (объём, сроки, ценность)

**Артефакты:**

- Декомпозиция эпика
- Заметки воркшопа приоритизации
- Согласованная базовая версия бэклога

### Уровень 5

**Проверять:**

- Планирует требования для крупных инициатив; согласовывает конкурирующие приоритеты
- Адаптирует методы (dual-track, уровни бэклога SAFe и т.п.) под контекст

**Артефакты:**

- Подход к требованиям для программы
- Журнал разрешения конфликтов
- Вклад в орг. стандарты

## RLMT — Управление отношениями со стейкхолдерами

### Уровень 4

**Проверять:**

- Ведёт план вовлечения своих стейкхолдеров (бизнес, дизайн, разработка, поддержка)
- Собирает обратную связь, закрывает проблемы, улучшает коммуникацию

**Артефакты:**

- Карта стейкхолдеров
- План вовлечения и коммуникаций
- Сводка обратной связи

### Уровень 5

**Проверять:**

- Единая точка контакта по продукту для ключевых групп
- Помогает принимать бизнес-решения; переводит стратегию в результаты поставки

**Артефакты:**

- Журнал решений с альтернативами
- Обновление для руководства
- Заметки по согласованию между командами

## BUSA — Анализ бизнес-ситуации

### Уровень 2

**Проверять:**

- Собирает данные для анализа проблемы: интервью, тикеты поддержки, метрики
- Помогает структурировать находки под руководством

**Артефакты:**

- Заметки исследования
- Черновик формулировки проблемы

### Уровень 3

**Проверять:**

- Исследует простые бизнес-ситуации для фичи или улучшения
- Формулирует проблему, гипотезу, рекомендации с доказательствами

**Артефакты:**

- Оценка возможности
- Заметки по корневой причине (5 почему / простая диаграмма Исикавы)

### Уровень 4

**Проверять:**

- Анализирует неоднозначные ситуации; целостный взгляд на проблемы и возможности
- Анализ корневых причин; рекомендации с учётом ограничений организации

**Артефакты:**

- Документ бизнес-анализа
- Сравнение вариантов
- Итоги воркшопа

### Уровень 5

**Проверять:**

- Ведёт сложный анализ бизнес-ситуации для стратегических инициатив
- Согласует выводы со стейкхолдерами уровня руководства

**Артефакты:**

- Стратегический бриф возможности
- Краткая сводка для руководства с рекомендациями

## FEAS — Оценка осуществимости

### Уровень 2

**Проверять:**

- Собирает данные для черновой оценки осуществимости (трудозатраты, зависимости, риски)

**Артефакты:**

- Чеклист осуществимости
- Черновая оценка размера

### Уровень 3

**Проверять:**

- Поддерживает бизнес-кейс: ощутимые затраты и выгоды, риски
- Сужает список вариантов вместе с разработкой и дизайном

**Артефакты:**

- Короткий бизнес-кейс
- Таблица сравнения вариантов

### Уровень 4

**Проверять:**

- Готовит бизнес-кейс с затратами и выгодами, влиянием и рисками для инициативы
- Привлекает внутренних и внешних стейкхолдеров за информацией

**Артефакты:**

- Документ бизнес-кейса
- Реестр рисков инициативы

## MEAS — Измерение и метрики

### Уровень 2

**Проверять:**

- Поддерживает сбор продуктовых метрик по шаблону (DAU, конверсия, NPS и т.п.)
- Готовит простые отчёты для команды

**Артефакты:**

- Еженедельный снимок метрик
- Заметки по настройке дашборда

### Уровень 3

**Проверять:**

- Определяет метрики для фичи (опережающие и запаздывающие); следит за качеством данных
- Интерпретирует регулярную аналитику для продуктовых решений

**Артефакты:**

- Дерево метрик для фичи
- Разбор эксперимента

### Уровень 4

**Проверять:**

- Приоритизирует показатели для продукта или стрима; проектирует отчётность
- Помогает командам с методами измерения

**Артефакты:**

- Рамка north star и входных метрик
- Кастомный отчёт или когортный анализ

### Уровень 5

**Проверять:**

- Задаёт цели измерения для продуктовой области; улучшает возможности измерения
- Консультирует по эффективному использованию метрик; вносит вклад в орг. стандарты

**Артефакты:**

- Стратегия измерения
- Вклад в глоссарий метрик организации

## DEMG — Управление поставкой

### Уровень 3

**Проверять:**

- Координирует регулярную поставку небольшой фичи: планирование, риски, статус
- Следует процессу поставки команды; отслеживает прогресс

**Артефакты:**

- План спринта или релиза
- Журнал рисков и проблем
- Статус-отчёт

### Уровень 4

**Проверять:**

- Ведёт поставку средних инициатив; планирование итераций, прирост ценности
- Сообщает о прогрессе и рисках; следит за качеством результатов

**Артефакты:**

- План поставки между командами
- Заметки обзора инкремента
- Действия ретро

## HCEV — Проектирование пользовательского опыта

### Уровень 2

**Проверять:**

- Понимает базовые принципы UX; описывает пользовательский сценарий для простой фичи
- Согласует объём с дизайном по макетам

**Артефакты:**

- Набросок пользовательского сценария
- Бриф фичи с UX-контекстом

### Уровень 3

**Проверять:**

- Формулирует UX-требования в спецификации; итерирует с дизайном на прототипах
- Учитывает удобство и доступность в критериях приёмки

**Артефакты:**

- Спецификация с разделом UX
- Заметки ревью прототипа

## USEV — Оценка пользовательского опыта

### Уровень 2

**Проверять:**

- Собирает обратную связь по прототипу или MVP по шаблону (интервью, опрос)

**Артефакты:**

- Гайд интервью и заметки
- Синтез обратной связи

### Уровень 3

**Проверять:**

- Проводит или организует оценку удобства; приоритизирует находки для бэклога

**Артефакты:**

- План теста удобства
- Отчёт с находками и рекомендациями

## RELM — Управление релизами

### Уровень 2

**Проверять:**

- По чеклисту готовит коммуникации релиза, заметки, координацию с QA и разработкой

**Артефакты:**

- Чеклист релиза продакта
- Черновик релиз-нот

### Уровень 3

**Проверять:**

- Координирует типовой релиз фичи: объём, коммуникации, мониторинг после релиза

**Артефакты:**

- План релиза
- Заметки мониторинга после релиза

### Уровень 4

**Проверять:**

- Планирует релизы с зависимостями, поэтапной раскаткой, критериями отката

**Артефакты:**

- План релиза между командами
- Разбор после релиза с метриками
