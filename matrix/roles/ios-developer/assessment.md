# Рекомендации по оценке: iOS-разработчик

Навык SFIA общий. Ниже — что проверять **в контексте этой роли**. Если навыка нет в списке — используйте универсальный текст SFIA.

## PROG — Программирование / разработка ПО

### Уровень 2

**Проверять:**

- Пишет простые экраны и утилиты на Swift (опционалы, коллекции, замыкания) по задаче
- Использует UIKit и/или SwiftUI на типовых задачах под менторством
- Не хранит секреты в коде; базово соблюдает privacy-ограничения
- Перед сдачей сам просматривает свой PR, правит замечания

**Артефакты:**

- PR с простой фичей или багфиксом
- Скрин/запись экрана по задаче
- Простой unit-тест по образцу команды

### Уровень 3

**Проверять:**

- Самостоятельно закрывает фичу целиком: сеть, состояние UI, ошибки и загрузка
- Уверенно применяет многопоточность (GCD и/или async/await), понимает ARC и retain-циклы
- Следует архитектурным соглашениям команды (MVC / MVVM / аналоги)
- Пишет и дополняет unit-тесты на новую логику; участвует в ревью кода

**Артефакты:**

- PR фичи с сетевым слоем и UI-состояниями
- Ревью с содержательными комментариями
- Разбор бага с корневой причиной в тикете

### Уровень 4

**Проверять:**

- Реализует сложные модули и интеграции: диплинки, фоновые задачи, SDK, межмодульное взаимодействие
- Влияет на выбор подходов, зависимостей (SPM и т.п.) и практик безопасности в команде
- Ведёт ревью коллег; проводит рефакторинг устаревшего кода с сохранением поведения
- Оценивает риски релиза (регрессии, миграции, совместимость OS и устройств)

**Артефакты:**

- ADR или RFC по модульности или архитектуре фичи
- Серия ревью с планкой качества
- Рефакторинг с метриками / разбор инцидента

### Уровень 5

**Проверять:**

- Берёт тех. ответственность за iOS-стрим: от требований до поставки и оценки качества
- Планирует разработку: выбирает SwiftUI или UIKit, границы модулей и feature-флаги — под задачу и контекст
- Контролирует стандарты команды, включая privacy, Keychain и безопасность сторонних зависимостей
- Вносит вклад в руководства по iOS-разработке сообщества или организации

**Артефакты:**

- Принятые стандарты и гайды
- План тех. инициативы с метриками успеха
- Менторство с измеримым ростом людей

## SWDN — Проектирование ПО

### Уровень 2

**Проверять:**

- Описывает простой экран или компонент: ответственность, входы и выходы, базовый поток данных
- Применяет паттерны команды (например, простой MVVM) под контролем

**Артефакты:**

- Схема или короткая заметка по дизайну к задаче
- Диаграмма потока данных экрана

### Уровень 3

**Проверять:**

- Проектирует умеренно сложный модуль: слои, интерфейсы, состояния, ошибки
- Учитывает жизненный цикл UIViewController/SwiftUI, навигацию, базовые нефункциональные требования

**Артефакты:**

- Проектный документ модуля
- Интерфейсы протоколов / границы модуля в PR

### Уровень 4

**Проверять:**

- Проектирует сложные модули и интеграции с компромиссами (модульность, тестируемость, производительность)
- Ведёт ревью дизайнов коллег; прототипирует спорные решения

**Артефакты:**

- ADR с разбором альтернатив
- Ревью архитектурного предложения

### Уровень 5

**Проверять:**

- Задаёт подход к проектированию и архитектуре для крупной зоны iOS-продукта
- Балансирует качество, безопасность и поддерживаемость; влияет на стандарты проектирования

**Артефакты:**

- Архитектурные принципы стрима
- Анализ влияния крупного изменения

## SINT — Интеграция систем и сборка

### Уровень 2

**Проверять:**

- Собирает проект в Xcode или по CI-инструкции команды, прогоняет заданные проверки
- Фиксирует падения сборки и тестов с воспроизведением

**Артефакты:**

- Лог успешной или упавшей сборки
- Скрин задачи CI

### Уровень 3

**Проверять:**

- Настраивает зависимости модуля (SPM/CocoaPods), понимает таргеты и схемы Xcode
- Чинит типовые поломки CI; готовит сборку для TestFlight или внутренней раздачи

**Артефакты:**

- PR с правкой Package.swift или конфига CI
- Успешная сборка в TestFlight

### Уровень 4

**Проверять:**

- Проектирует сложные интеграционные сборки, модульную сборку, ускорение CI
- Согласует интеграцию с платформенной или бэкенд-командой

**Артефакты:**

- Ускорение пайплайна с метрикой времени
- План интеграции крупной фичи

### Уровень 5

**Проверять:**

- Развивает CI/CD и практики интеграции iOS-направления
- Выбирает инструменты сборки и дистрибуции, задаёт стандарты

**Артефакты:**

- Стандарт CI для мобилки
- Внедрение новых инструментов сборки

## TEST — Функциональное тестирование

### Уровень 1

**Проверять:**

- Прогоняет готовый чеклист по своей задаче под наставничеством

**Артефакты:**

- Отмеченный чеклист в тикете

### Уровень 2

**Проверять:**

- Составляет короткий чеклист к своей фиче (основной сценарий и базовые негативные)
- Заводит баги с шагами, окружением (устройство/OS), ожидаемым и фактическим результатом

**Артефакты:**

- Чеклист к PR
- Заведённый баг с полным описанием

## HCEV — Проектирование пользовательского опыта

### Уровень 2

**Проверять:**

- Верстает простые экраны по макету (UIKit/SwiftUI), соблюдает отступы и системные компоненты

**Артефакты:**

- PR с UI по макету
- Сравнение с дизайном

### Уровень 3

**Проверять:**

- Собирает сложные экраны, кастомные компоненты, стандартную навигацию
- Согласует реализуемость с дизайнером; учитывает Dynamic Type и тёмную тему, где принято

**Артефакты:**

- Переиспользуемый UI-компонент
- Комментарии и итерации с дизайном

### Уровень 4

**Проверять:**

- Проектирует UI со сложным взаимодействием: кастомные переходы, сложные состояния
- Влияет на паттерны UI в команде и дизайн-системе

**Артефакты:**

- Компонент дизайн-системы
- Кастомный переход или сложная анимация

## ACIN — Доступность и инклюзивность

### Уровень 2

**Проверять:**

- Прогоняет базовые проверки VoiceOver и Dynamic Type по чеклисту

**Артефакты:**

- Заметки прогона доступности

### Уровень 3

**Проверять:**

- Делает подписи и признаки VoiceOver для своих экранов
- Проверяет контраст и крупный текст на типовых сценариях

**Артефакты:**

- PR с правками доступности
- Чеклист VoiceOver по фиче

## NFTS — Нефункциональное тестирование

### Уровень 2

**Проверять:**

- Смотрит Instruments (Time Profiler / Allocations) на явные проблемы своей фичи
- Ловит очевидные зависания главного потока и лишние перерисовки

**Артефакты:**

- Скрин или заметка Instruments
- Фикс подтормаживаний или памяти в PR

### Уровень 3

**Проверять:**

- Планирует простые проверки производительности и стабильности для рискованных изменений
- Умеет интерпретировать базовые метрики крэшей и зависаний

**Артефакты:**

- Короткий чеклист нефункциональных проверок к релизу фичи
- Разбор крэша

## METL — Методы и инструменты

### Уровень 2

**Проверять:**

- Работает в Xcode и Git по гайдам команды; обновляет README и заметки по просьбе

**Артефакты:**

- PR по шаблону команды

### Уровень 3

**Проверять:**

- Настраивает линтеры, форматтеры и схемы в своём модуле; чинит типовые проблемы с инструментами

**Артефакты:**

- PR с конфигом SwiftLint/SwiftFormat и т.п.

### Уровень 4

**Проверять:**

- Рекомендует и внедряет инструменты iOS-команды; пишет короткие гайды

**Артефакты:**

- Гайд по инструменту
- Внедрение нового шаблона или генератора

### Уровень 5

**Проверять:**

- Выбирает набор инструментов для направления; оценивает их пользу

**Артефакты:**

- Решение о выборе инструмента с критериями
- Политика использования AI/IDE в команде

## RELM — Управление релизами

### Уровень 2

**Проверять:**

- По чеклисту готовит материалы релиза (заметки, сборка) под контролем

**Артефакты:**

- Заполненный чеклист релиза

### Уровень 3

**Проверять:**

- Проводит типовой релиз фичи в TestFlight и стор по процессу команды
- Ловит блокеры релиза

**Артефакты:**

- Релиз-ноты и статус раскатки

### Уровень 4

**Проверять:**

- Планирует релиз с зависимостями, поэтапной раскаткой и feature-флагами

**Артефакты:**

- План релиза
- Разбор после релиза
