# Рекомендации по оценке: QA-инженер

Навык SFIA общий. Ниже — что проверять **в контексте этой роли**. Если навыка нет в списке — используйте универсальный текст SFIA.

## PROG — Программирование / разработка ПО

### Уровень 2

**Проверять:**

- Пишет простые тестовые скрипты/хелперы на стеке автоматизации команды
- Поддерживает читаемые page objects / фикстуры по образцу
- Соблюдает секреты/тестовые данные — не коммитит credentials

**Артефакты:**

- PR с простым автотестом
- Хелпер/фикстура

### Уровень 3

**Проверять:**

- Самостоятельно автоматизирует повторяемые сценарии умеренной сложности
- Стабилизирует flaky-тесты; понимает границы unit vs e2e
- Ревьюит тестовый код коллег

**Артефакты:**

- Набор автотестов на фичу
- Фикс flaky с объяснением
- Ревью test PR

## TEST — Функциональное тестирование

### Уровень 2

**Проверять:**

- Помогает проектировать кейсы; готовит данные; выполняет ручные и automated checks
- Отчитывается о findings, issues и рисках

**Артефакты:**

- Набор кейсов
- Отчёт прогона
- Баги с деталями

### Уровень 3

**Проверять:**

- Самостоятельно проектирует тест-дизайн фичи: сценарии, границы, регрессия зоны
- Участвует в ревью требований/дизайна; ведёт exploratory testing
- Автоматизирует повторяемое; даёт go/no-go на уровне фичи

**Артефакты:**

- Тест-план фичи
- Отчёт exploratory / регрессии
- Уточнённые AC в тикете

### Уровень 4

**Проверять:**

- Выбирает стратегию functional testing с учётом риска и критичности
- Развивает automation framework; отчитывается в т.ч. по работе других

**Артефакты:**

- Стратегия тестирования стрима
- Framework contribution
- Сводный quality report

### Уровень 5

**Проверять:**

- Ведёт functional testing на всех этапах продукта
- Задаёт методы/стандарты; улучшает покрытие и эффективность

**Артефакты:**

- Политика/стандарт тестирования
- Метрики покрытия/эффективности

## NFTS — Нефункциональное тестирование

### Уровень 1

**Проверять:**

- Выполняет готовые performance/security smoke-скрипты под контролем

**Артефакты:**

- Лог прогона

### Уровень 3

**Проверять:**

- Проектирует NFT-кейсы (performance, стабильность и др. по контексту)
- Готовит данные/окружения, близкие к prod; анализирует результаты

**Артефакты:**

- NFT test plan
- Отчёт load/perf с выводами

### Уровень 4

**Проверять:**

- Выбирает NFT-подходы для критичных систем; координирует с разработкой
- Строит повторяемые автоматизированные NFT

**Артефакты:**

- Стратегия NFT
- Автоматизированный perf suite

### Уровень 5

**Проверять:**

- Лидирует NFT на продукте; вносит вклад в орг. стандарты

**Артефакты:**

- Стандарт NFT
- Улучшение надёжности тестовых стендов

## QUAS — Обеспечение качества

### Уровень 2

**Проверять:**

- Собирает evidence по чеклистам качества; замечает очевидные non-compliance

**Артефакты:**

- Заполненный QA checklist

### Уровень 3

**Проверять:**

- Проверяет, что нужные тестовые/quality-control активности реально были
- Фиксирует non-compliances относительно стандартов команды

**Артефакты:**

- Audit notes
- Список non-compliance с ссылками

### Уровень 4

**Проверять:**

- Планирует assessment activity; готовит compliance reports
- Предлагает corrective actions и консультирует по стандартам

**Артефакты:**

- Formal review report
- План corrective actions

### Уровень 5

**Проверять:**

- Ведёт assurance сложных областей; надзирает assurance других

**Артефакты:**

- Cross-area quality assessment
- Улучшение control mechanisms

## USEV — Оценка пользовательского опыта

### Уровень 2

**Проверять:**

- Помогает готовить среду и собирать feedback по прототипам

**Артефакты:**

- Сырые заметки feedback

### Уровень 3

**Проверять:**

- Проводит usability/a11y evaluation компонентов
- Фиксирует findings и рекомендует действия

**Артефакты:**

- Evaluation report
- Список UX issues с приоритетом

### Уровень 4

**Проверять:**

- Выбирает методы оценки UX; валидирует usability/a11y/security требования
- Приоритизирует проблемы для design/dev

**Артефакты:**

- План evaluation
- Сводка для продукт/дизайн

## ACIN — Доступность и инклюзивность

### Уровень 2

**Проверять:**

- Выполняет predefined a11y-тесты; документирует результаты

**Артефакты:**

- A11y test log

### Уровень 3

**Проверять:**

- Проектирует и выполняет a11y-тесты фичи (WCAG/платформенные критерии)
- Структурированно отчитывается и эскалирует сложное

**Артефакты:**

- A11y test plan + report

### Уровень 4

**Проверять:**

- Влияет на дизайн с точки зрения accessibility; оценивает compliance-риски
- Планирует a11y-тестирование релиза

**Артефакты:**

- A11y risk assessment
- Стандарт проверок для стрима

## METL — Методы и инструменты

### Уровень 2

**Проверять:**

- Работает в TMS/баг-трекере/CI тестов по гайдам команды

**Артефакты:**

- Оформленные кейсы/баги в системе

### Уровень 3

**Проверять:**

- Настраивает тестовые tools в известном контексте; обновляет инструкции

**Артефакты:**

- Дока по tool
- Правка CI тестов

### Уровень 4

**Проверять:**

- Рекомендует методы/инструменты тестирования; помогает с adoption

**Артефакты:**

- Сравнение tools
- Гайд внедрения

### Уровень 5

**Проверять:**

- Выбирает toolchain качества; оценивает value; влияет на политики

**Артефакты:**

- Decision record
- Политика инструментов QA

## SINT — Интеграция систем и сборка

### Уровень 2

**Проверять:**

- Поднимает тестовый стенд/сборку по инструкции; гоняет integration smoke

**Артефакты:**

- Лог smoke на стенде

### Уровень 3

**Проверять:**

- Собирает тестовые контуры для фичи; диагностирует типовые env-проблемы

**Артефакты:**

- Описание тест-окружения
- Фикс конфигурации стенда

## RELM — Управление релизами

### Уровень 2

**Проверять:**

- Участвует в release checklist: прогон smoke, фиксация блокеров

**Артефакты:**

- Отмеченный release QA checklist

### Уровень 3

**Проверять:**

- Даёт quality sign-off на типовой релиз; эскалирует риски

**Артефакты:**

- Go/no-go с обоснованием

### Уровень 4

**Проверять:**

- Планирует quality gates релиза; координирует проверки across teams

**Артефакты:**

- Release test plan
- Post-release quality review

## SWDN — Проектирование ПО

### Уровень 3

**Проверять:**

- Участвует в дизайне тестовой стратегии модуля: что автоматизировать, какие риски
- Предлагает testability-улучшения дизайну/разработке

**Артефакты:**

- Заметки testability review
- Схема уровней тестов

### Уровень 4

**Проверять:**

- Проектирует test architecture стрима (пирамида, данные, окружения)

**Артефакты:**

- Test architecture doc
