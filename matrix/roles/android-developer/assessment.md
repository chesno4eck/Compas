# Рекомендации по оценке: Android-разработчик

Навык SFIA общий. Ниже — что проверять **в контексте этой роли**. Если навыка нет в списке — используйте универсальный текст SFIA.

## PROG — Программирование / разработка ПО

### Уровень 2

**Проверять:**

- Пишет простые экраны и утилиты на Kotlin (nullable, коллекции, лямбды) по задаче
- Использует Jetpack Compose на типовых задачах под менторством
- Не хранит секреты в коде; базово соблюдает privacy-ограничения
- Перед сдачей сам просматривает свой PR, правит замечания

**Артефакты:**

- PR с простой фичей или багфиксом
- Скрин/запись экрана по задаче
- Простой unit-тест по образцу команды

### Уровень 3

**Проверять:**

- Самостоятельно закрывает фичу целиком: сеть (Ktor), состояние UI (StateFlow), Room, ошибки и загрузка
- Уверенно применяет Kotlin Coroutines, понимает отмену, скоупы и потоки
- Следует архитектурным соглашениям команды (multi-module Clean Architecture: core/features); внедряет зависимости через Koin
- Пишет и дополняет unit-тесты на новую логику; участвует в ревью кода

**Артефакты:**

- PR фичи с сетевым слоем и UI-состояниями
- Ревью с содержательными комментариями
- Разбор бага с корневой причиной в тикете

### Уровень 4

**Проверять:**

- Реализует сложные модули и интеграции: диплинки, фоновые задачи, SDK, межмодульное взаимодействие core/features
- Влияет на выбор подходов, зависимостей (Gradle-модули, Koin) и практик безопасности в команде
- Ведёт ревью коллег; проводит рефакторинг устаревшего кода с сохранением поведения
- Оценивает риски релиза (регрессии, миграции Room, совместимость OS и устройств)

**Артефакты:**

- ADR или RFC по модульности или архитектуре фичи
- Серия ревью с планкой качества
- Рефакторинг с метриками / разбор инцидента

### Уровень 5

**Проверять:**

- Берёт тех. ответственность за Android-стрим: от требований до поставки и оценки качества
- Планирует разработку: границы модулей core/features, Compose и feature-флаги — под задачу и контекст
- Контролирует стандарты команды, включая privacy, Keystore и безопасность сторонних зависимостей
- Вносит вклад в руководства по Android-разработке сообщества или организации

**Артефакты:**

- Принятые стандарты и гайды
- План тех. инициативы с метриками успеха
- Менторство с измеримым ростом людей

## SWDN — Проектирование ПО

### Уровень 2

**Проверять:**

- Описывает простой экран или компонент: ответственность, входы и выходы, базовый поток данных
- Применяет паттерны команды (слои Clean Architecture, простой экран на Compose) под контролем

**Артефакты:**

- Схема или короткая заметка по дизайну к задаче
- Диаграмма потока данных экрана

### Уровень 3

**Проверять:**

- Проектирует умеренно сложный модуль: слои, интерфейсы, состояния (StateFlow), ошибки
- Учитывает жизненный цикл Compose, Navigation Compose, базовые нефункциональные требования

**Артефакты:**

- Проектный документ модуля
- Интерфейсы / границы модуля в PR

### Уровень 4

**Проверять:**

- Проектирует сложные модули и интеграции с компромиссами (модульность core/features, тестируемость, производительность)
- Ведёт ревью дизайнов коллег; прототипирует спорные решения

**Артефакты:**

- ADR с разбором альтернатив
- Ревью архитектурного предложения

### Уровень 5

**Проверять:**

- Задаёт подход к проектированию и архитектуре для крупной зоны Android-продукта
- Балансирует качество, безопасность и поддерживаемость; влияет на стандарты проектирования

**Артефакты:**

- Архитектурные принципы стрима
- Анализ влияния крупного изменения

## SINT — Интеграция систем и сборка

### Уровень 2

**Проверять:**

- Собирает проект в Android Studio / Gradle или по CI-инструкции команды, прогоняет заданные проверки
- Фиксирует падения сборки и тестов с воспроизведением

**Артефакты:**

- Лог успешной или упавшей сборки
- Скрин задачи CI

### Уровень 3

**Проверять:**

- Настраивает зависимости модуля (Gradle, Koin), понимает multi-module структуру core/features
- Чинит типовые поломки CI; готовит сборку для внутренней раздачи или Play Internal Testing

**Артефакты:**

- PR с правкой Gradle или конфига CI
- Успешная сборка для внутренней раздачи / Play Internal

### Уровень 4

**Проверять:**

- Проектирует сложные интеграционные сборки, модульную сборку, ускорение CI
- Согласует интеграцию с платформенной или бэкенд-командой

**Артефакты:**

- Ускорение пайплайна с метрикой времени
- План интеграции крупной фичи

### Уровень 5

**Проверять:**

- Развивает CI/CD и практики интеграции Android-направления
- Выбирает инструменты сборки и дистрибуции, задаёт стандарты

**Артефакты:**

- Стандарт CI для мобилки
- Внедрение новых инструментов сборки

## TEST — Функциональное тестирование

### Уровень 1

**Проверять:**

- Прогоняет готовый чеклист по своей задаче под наставничеством

**Артефакты:**

- Отмеченный чеклист в тикете

### Уровень 2

**Проверять:**

- Составляет короткий чеклист к своей фиче (основной сценарий и базовые негативные)
- Заводит баги с шагами, окружением (устройство/OS), ожидаемым и фактическим результатом

**Артефакты:**

- Чеклист к PR
- Заведённый баг с полным описанием

## HCEV — Проектирование пользовательского опыта

### Уровень 2

**Проверять:**

- Верстает простые экраны по макету (Jetpack Compose), соблюдает отступы и системные/Material-компоненты

**Артефакты:**

- PR с UI по макету
- Сравнение с дизайном

### Уровень 3

**Проверять:**

- Собирает сложные экраны, кастомные composable, стандартную навигацию (Navigation Compose)
- Согласует реализуемость с дизайнером; учитывает масштаб шрифта и тёмную тему, где принято

**Артефакты:**

- Переиспользуемый UI-компонент
- Комментарии и итерации с дизайном

### Уровень 4

**Проверять:**

- Проектирует UI со сложным взаимодействием: кастомные переходы, сложные состояния
- Влияет на паттерны UI в команде и дизайн-системе

**Артефакты:**

- Компонент дизайн-системы
- Кастомный переход или сложная анимация

## ACIN — Доступность и инклюзивность

### Уровень 2

**Проверять:**

- Прогоняет базовые проверки TalkBack и масштаба шрифта по чеклисту

**Артефакты:**

- Заметки прогона доступности

### Уровень 3

**Проверять:**

- Делает contentDescription и семантику Compose для своих экранов
- Проверяет контраст и крупный текст на типовых сценариях

**Артефакты:**

- PR с правками доступности
- Чеклист TalkBack по фиче

## NFTS — Нефункциональное тестирование

### Уровень 2

**Проверять:**

- Смотрит Android Studio Profiler (CPU / Memory) на явные проблемы своей фичи
- Ловит очевидные зависания главного потока, jank и лишние рекомпозиции Compose

**Артефакты:**

- Скрин или заметка Profiler
- Фикс подтормаживаний или памяти в PR

### Уровень 3

**Проверять:**

- Планирует простые проверки производительности и стабильности для рискованных изменений
- Умеет интерпретировать базовые метрики крэшей и ANR в Sentry

**Артефакты:**

- Короткий чеклист нефункциональных проверок к релизу фичи
- Разбор крэша в Sentry

## METL — Методы и инструменты

### Уровень 2

**Проверять:**

- Работает в Android Studio и Git по гайдам команды; логирует через Timber по образцу; обновляет README и заметки по просьбе

**Артефакты:**

- PR по шаблону команды

### Уровень 3

**Проверять:**

- Настраивает линтеры, форматтеры и Gradle в своём модуле; чинит типовые проблемы с инструментами

**Артефакты:**

- PR с конфигом ktlint/detekt и т.п.

### Уровень 4

**Проверять:**

- Рекомендует и внедряет инструменты Android-команды; пишет короткие гайды

**Артефакты:**

- Гайд по инструменту
- Внедрение нового шаблона или генератора

### Уровень 5

**Проверять:**

- Выбирает набор инструментов для направления; оценивает их пользу

**Артефакты:**

- Решение о выборе инструмента с критериями
- Политика использования AI/IDE в команде

## RELM — Управление релизами

### Уровень 2

**Проверять:**

- По чеклисту готовит материалы релиза (заметки, сборка) под контролем

**Артефакты:**

- Заполненный чеклист релиза

### Уровень 3

**Проверять:**

- Проводит типовой релиз фичи во внутреннюю раздачу и Play Console по процессу команды
- Ловит блокеры релиза

**Артефакты:**

- Релиз-ноты и статус раскатки

### Уровень 4

**Проверять:**

- Планирует релиз с зависимостями, поэтапной раскаткой и feature-флагами

**Артефакты:**

- План релиза
- Разбор после релиза
