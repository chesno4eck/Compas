# Рекомендации по оценке: Backend-разработчик

Навык SFIA общий. Ниже — что проверять **в контексте этой роли**. Если навыка нет в списке — используйте универсальный текст SFIA.

## PROG — Программирование / разработка ПО

### Уровень 2

**Проверять:**

- Пишет простые хендлеры и утилиты на Go (структуры, ошибки, слайсы) по задаче
- Использует Gin на типовых задачах под менторством: роут, хендлер, JSON-ответ
- Не хранит секреты в коде; логирует через slog по образцу команды
- Перед сдачей сам просматривает свой PR, правит замечания

**Артефакты:**

- PR с простой фичей или багфиксом
- Простой unit-тест по образцу команды

### Уровень 3

**Проверять:**

- Самостоятельно закрывает фичу целиком: хендлер, сервис, доступ к данным (PostgreSQL / Redis), ошибки и логирование
- Уверенно применяет Go: context, интерфейсы, обработка ошибок; следует слоям команды (Gin, пакеты)
- Пишет и дополняет unit-тесты на новую логику; участвует в ревью кода
- Описывает HTTP API в OpenAPI по принятому шаблону команды

**Артефакты:**

- PR фичи с хендлером, доступом к данным и обработкой ошибок
- Ревью с содержательными комментариями
- Разбор бага с корневой причиной в тикете

### Уровень 4

**Проверять:**

- Реализует сложные модули и интеграции: контракты OpenAPI, кэш Redis, асинхронные сценарии; понимает, когда уместен gRPC вместо HTTP
- Влияет на выбор подходов, зависимостей и практик безопасности; оценивает Kafka и другие интеграции под задачу
- Ведёт ревью коллег; проводит рефакторинг устаревшего кода с сохранением поведения
- Оценивает риски релиза (регрессии, миграции goose, обратная совместимость API)

**Артефакты:**

- ADR или RFC по контракту API, модульности или асинхронной интеграции
- Серия ревью с планкой качества
- Рефакторинг с метриками / разбор инцидента

### Уровень 5

**Проверять:**

- Берёт тех. ответственность за бэкенд-стрим: от требований до поставки и оценки качества
- Планирует разработку: HTTP или gRPC, синхрон или Kafka, границы сервисов и feature-флаги — под задачу и контекст
- Контролирует стандарты команды, включая slog, метрики Prometheus и безопасность зависимостей
- Вносит вклад в руководства по бэкенд-разработке сообщества или организации

**Артефакты:**

- Принятые стандарты и гайды
- План тех. инициативы с метриками успеха
- Менторство с измеримым ростом людей

## SWDN — Проектирование ПО

### Уровень 2

**Проверять:**

- Описывает простой хендлер или пакет: ответственность, входы и выходы, базовый поток данных
- Применяет паттерны команды (слои хендлер / сервис / репозиторий) под контролем

**Артефакты:**

- Схема или короткая заметка по дизайну к задаче
- Диаграмма потока запроса

### Уровень 3

**Проверять:**

- Проектирует умеренно сложный модуль: слои, интерфейсы, ошибки, контракт OpenAPI
- Учитывает транзакции, идемпотентность и базовые нефункциональные требования

**Артефакты:**

- Проектный документ модуля
- Интерфейсы пакетов / контракт API в PR

### Уровень 4

**Проверять:**

- Проектирует сложные модули и интеграции с компромиссами (модульность, тестируемость, производительность, HTTP vs gRPC, синхрон vs Kafka)
- Ведёт ревью дизайнов коллег; прототипирует спорные решения

**Артефакты:**

- ADR с разбором альтернатив
- Ревью архитектурного предложения

### Уровень 5

**Проверять:**

- Задаёт подход к проектированию и архитектуре для крупной зоны бэкенд-продукта
- Балансирует качество, безопасность и поддерживаемость; влияет на стандарты проектирования

**Артефакты:**

- Архитектурные принципы стрима
- Анализ влияния крупного изменения

## SINT — Интеграция систем и сборка

### Уровень 2

**Проверять:**

- Собирает и прогоняет пайплайн сервиса по готовому CI/CD-шаблону DevOps
- Фиксирует падения сборки и тестов с воспроизведением; не меняет сам шаблон без необходимости

**Артефакты:**

- Лог успешной или упавшей сборки в CI
- Скрин задачи пайплайна

### Уровень 3

**Проверять:**

- Адаптирует CI/CD-шаблон DevOps под сервис: зависимости, `go test`, артефакты, переменные
- Чинит типовые поломки сборки своего сервиса; эскалирует изменения общего шаблона в DevOps

**Артефакты:**

- PR с адаптацией шаблона или конфига сборки сервиса
- Разбор поломки CI с корневой причиной

## TEST — Функциональное тестирование

### Уровень 1

**Проверять:**

- Прогоняет готовые тесты и чеклист по своей задаче под наставничеством
- Минимум: добавляет или прогоняет smoke-тест на happy path эндпоинта

**Артефакты:**

- Отмеченный чеклист в тикете
- Smoke-тест или лог прогона happy path

### Уровень 2

**Проверять:**

- Пишет unit-тесты на свою логику: основной сценарий и базовые негативные
- Заводит баги с шагами, окружением, ожидаемым и фактическим результатом

**Артефакты:**

- Unit-тесты в PR
- Заведённый баг с полным описанием

### Уровень 3

**Проверять:**

- Проектирует тест-кейсы на бизнес-логику сервиса: границы, негативные сценарии
- Пишет table-driven тесты в Go на новую логику; мокает внешние зависимости на уровне пакета

**Артефакты:**

- Table-driven тесты в PR
- Набор кейсов к фиче (позитив / негатив / границы)

### Уровень 4

**Проверять:**

- Задаёт тест-стратегию сервиса: что покрывать unit, интеграционными и контрактными тестами
- Проектирует mock/stub внешних зависимостей (БД, Redis, HTTP, очереди) без хрупких тестов

**Артефакты:**

- Тест-стратегия сервиса
- Фреймворк или набор стабов/моков в репозитории

### Уровень 5

**Проверять:**

- Задаёт стандарт функционального тестирования для бэкенд-команды
- Улучшает покрытие и эффективность; вносит вклад в практики качества направления

**Артефакты:**

- Стандарт или гайд по тестированию бэкенда
- Метрики покрытия / стабильности тестов

## NFTS — Нефункциональное тестирование

### Уровень 3

**Проверять:**

- Планирует и проводит нагрузочные тесты своего сервиса (латентность, RPS, деградация под нагрузкой)
- Профилирует Go (pprof / trace) на узких местах CPU, аллокаций и I/O

**Артефакты:**

- Отчёт нагрузочного прогона с выводами
- Профиль pprof или фикс узкого места в PR

### Уровень 4

**Проверять:**

- Задаёт нагрузочную стратегию для группы сервисов: сценарии, SLO, стенды, повтор
- Согласует нагрузку с зависимостями (PostgreSQL, Redis) и интерпретирует системные узкие места

**Артефакты:**

- Стратегия нагрузочного тестирования
- Сводка узких мест и план улучшений

## METL — Методы и инструменты

### Уровень 2

**Проверять:**

- Работает в IDE и Git по гайдам команды; применяет goose и slog по образцу; обновляет README по просьбе

**Артефакты:**

- PR по шаблону команды

### Уровень 3

**Проверять:**

- Настраивает линтеры, форматтеры и тестовые хелперы в своём пакете; чинит типовые проблемы с инструментами

**Артефакты:**

- PR с конфигом линтера, Makefile или тестовым хелпером

### Уровень 4

**Проверять:**

- Рекомендует и внедряет инструменты бэкенд-команды (покрытие тестами, gRPC, миграции); пишет короткие гайды

**Артефакты:**

- Гайд по инструменту
- Внедрение шаблона тестов, генератора или клиента gRPC

### Уровень 5

**Проверять:**

- Выбирает набор инструментов для направления; оценивает их пользу

**Артефакты:**

- Решение о выборе инструмента с критериями
- Политика использования AI/IDE в команде

## RELM — Управление релизами

### Уровень 3

**Проверять:**

- Проводит типовой релиз фичи в прод по процессу команды
- Ловит блокеры релиза, включая миграции

**Артефакты:**

- Релиз-ноты и статус раскатки

### Уровень 4

**Проверять:**

- Планирует релиз с зависимостями, поэтапной раскаткой, feature-флагами и порядком миграций

**Артефакты:**

- План релиза
- Разбор после релиза

## DBDS — Проектирование баз данных

### Уровень 3

**Проверять:**

- Самостоятельно проектирует простые таблицы, индексы и миграции для фичи
- Выбирает, что кэшировать в Redis; понимает транзакции и типовые ловушки (N+1, отсутствие индекса)

**Артефакты:**

- Миграция goose с индексами и ограничениями
- EXPLAIN или заметка по запросу в PR

### Уровень 4

**Проверять:**

- Проектирует сложные схемы с учётом нагрузки, доступности и эволюции API
- Применяет партиционирование и оптимизацию запросов; оценивает PostgreSQL vs MongoDB vs Redis
- Ревьюит миграции и запросы коллег

**Артефакты:**

- ADR по схеме, партиционированию или выбору хранилища
- Ревью миграции с замечаниями по нагрузке

### Уровень 5

**Проверять:**

- Задаёт подходы к проектированию БД для бэкенд-направления
- Консультирует по выбору СУБД, схемам и практикам миграций; обеспечивает производительность и доступность

**Артефакты:**

- Стандарт проектирования данных / миграций
- Экспертная рекомендация по хранилищу

## DTAN — Моделирование и проектирование данных

### Уровень 3

**Проверять:**

- Моделирует данные фичи: сущности, связи, ограничения
- Объясняет, когда документная модель (MongoDB) уместнее реляционной, и когда нет

**Артефакты:**

- Модель данных фичи
- Заметка с обоснованием модели хранения

### Уровень 4

**Проверять:**

- Исследует требования к данным при неоднозначности; выбирает уровень детализации модели
- Консультирует коллег по структурам данных сервиса и границам агрегатов

**Артефакты:**

- Логическая модель домена
- Ревью модели данных коллеги

### Уровень 5

**Проверять:**

- Задаёт стандарты моделирования данных для бэкенд-сервисов
- Согласует модели между сервисами; следит за эволюцией схем и совместимостью

**Артефакты:**

- Стандарт моделирования данных
- Карта сущностей между сервисами

## MEAS — Измерение и метрики

### Уровень 2

**Проверять:**

- Добавляет базовые метрики сервиса по шаблону команды (Prometheus: RPS, ошибки, латентность)
- Находит свой сервис в Grafana и смотрит, что метрики пишутся

**Артефакты:**

- PR с метриками по шаблону
- Скрин дашборда Grafana по сервису

### Уровень 3

**Проверять:**

- Выбирает, какие метрики нужны сервису: RED/USE, бизнес-счётчики, saturation PostgreSQL/Redis
- Интерпретирует дашборды Grafana и логи OpenSearch при разборе инцидента или деградации

**Артефакты:**

- Набор метрик в PR с обоснованием
- Разбор инцидента со ссылкой на графики

### Уровень 4

**Проверять:**

- Проектирует метрики и алерты для сервиса или группы сервисов: пороги, SLO, шумоподавление
- Помогает команде выбрать, что измерять и как реагировать

**Артефакты:**

- Схема метрик и алертов
- Правила алертов с обоснованием порогов

### Уровень 5

**Проверять:**

- Задаёт стандарт метрик и алертов на микросервисы направления
- Консультирует по эффективному использованию Prometheus/Grafana; улучшает наблюдаемость

**Артефакты:**

- Стандарт наблюдаемости бэкенда
- Глоссарий метрик микросервисов
